## §1 Position and scope

E4 fills the design-volume row "EN-ification / zh-ification / translation": detection face scattered (the bilingual sync law is a
manual procedure on the paper line), application face absent, data face absent. E4 is the specification of
a **bidirectional zh↔en translation pipeline** for prose faces (repo docs, paper faces, submission-facing
text), with four mandatory linkages (§3), one LLM stage that must carry per-segment model annotation (§5),
one human ten-point single-face gate (§6), and a policy pre-check gate (§7).

**Anti-double-track boundary** (pre-integration audit §2 note 3, first-hand line anchors): `tools/evolve.py`
already dispatches a one-way EN-ification replacement program — `KIND_TOPIC` maps
`"norm-regression"`/`"longtail-translation"` to topic `"translation"` (`tools/evolve.py:330-337`), candidates
derive from the norm_lint translatable mass (`tools/evolve.py:810-822`, mass assembled at `:535`), and the
approach is mapping-table replacement with `.zh.md` archive siblings, keeping "code identifiers, CLI flags,
schema field names and exit codes unchanged" (`tools/evolve.py:231-250`). That slot is **one-way
replacement routing, not a translation engine** (no LLM interface, no bidirectional pipeline, no four
linkages). Division of labor: E4 = zh↔en bidirectional annotated pipeline (this SPEC); the evolve slot =
EN-ification single-direction replacement routing. E4 consumes the slot's signal as a candidate feed; it
does not duplicate the mapping-table replacement program.

## §2 Direction model

Two directions, one pipeline shape:

| key | direction | target register | direction-specific rules |
|---|---|---|---|
| `zh2en` | Chinese source → English target | repo-face English / paper-face English | English register inspected against the AI-flavor register (§3 L4); punctuation locale switch (full-width → half-width); CJK leakage zero on target |
| `en2zh` | English source → Chinese target | project-glossary Chinese | terminology injected from the termbase (§3 L1); the project glossary §1 rule 0 applies (standard-meaning terms used directly, not re-defined); identifier/flag preservation identical to `zh2en` |

Both directions preserve, byte-identical: code identifiers, CLI flags, schema field names, file paths, exit
codes, math, citations, and code blocks (precedent rule wording at `tools/evolve.py:245-247`). Segmentation
(§4 P1) is what makes this preservable: only prose segments enter translation.

## §3 Four linkages

Every repo-face run applies all four, in this order, unless the run manifest narrows the set (§9). Each
linkage has a data face and a mechanical verify face; the data faces are seeds of the sibling engines plus
read-only snapshots of the originals (§12).

| # | linkage | acts on | data face (source of truth) | mechanical verify face |
|---|---|---|---|---|
| L1 | normalization | term choice and consistency | E3 seed `seeds/termbase/termbase.json`; original `D:/ComplexAnalysis/规范术语/术语表-通用-项目级-20260921.md` (§4.0 adjudication tables) | term-consistency pass over the translated face (engine face, growing) |
| L2 | standardization | jargon → standard-term replacement | E2 seed `seeds/jargon/jargon-map.json`; in-repo md form already live: `docs/jargon-to-standard-mapping-v1.md` (norm_lint default, `tools/norm_lint.py:84`); chain: annotation whitepaper v1.8 §4 | `norm_lint --jargon-map` report: zero jargon findings on the translated face |
| L3 | internationalization | locale and format face | this SPEC §2 preservation list + `norm_lint --cjk-threshold` (zero-CJK end state) + em-dash density rule (glossary §4.6 C / §5: English face em-dash ≤ 1 per 1000 characters) | `norm_lint` CJK check zero-hit; em-dash battery zero-hit; preservation list diff zero-drift |
| L4 | de-AI-flavor | AI-flavor lexicon and pattern sweep | E1 seed `seeds/ai_flavor/word-map.json` (growing); register originals: glossary §4.6 A/C and §5 (AI-flavor Chinese words, patterns with false-positive bounds, English word/pattern/structure families); battery precedent `D:/ComplexAnalysis/attn/_vacgen_20261112/selftest/ai_flavor_selfcheck.sh` (36 facets + em-dash battery, detection only, exit 0/1) | AI-flavor battery zero-hit (exit 0) on the translated face |

L4 false-positive bounds travel with the register (glossary §4.6 C: pattern evidence is the weakest class;
technical contrast sentences are legitimate; the uniform-paragraph metric is retired). A linkage hit is a
finding, not an auto-rewrite: rewrites go through the linkage application stage with the same per-segment
ledger discipline as translation (§5, §9).

## §4 Pipeline stages

| stage | name | contract |
|---|---|---|
| P0 | policy pre-check (§7) | hard gate; annotated before any translation; refusal is a legal outcome |
| P1 | segmentation | split prose into segments; protect code, identifiers, flags, math, citations, paths; emit segment ledger (§9) |
| P2 | LLM translation (§5) | per-segment, at a model site, per-segment annotation mandatory; zero silent machine translation |
| P3 | linkage application (§3) | L1→L2→L3→L4 over translated segments; rewrites land in the same ledger |
| P4 | mechanical verification | `norm_lint --jargon-map` + CJK threshold, `doc_lint`, AI-flavor battery, `--selftest` of every touched tool |
| P5 | human ten-point single-face (§6) | manual gate; substitutes machine checks where they are blind |
| P6 | ledger close | bilingual/sync delta ledger + per-segment provenance appended; ledger is append-only |

## §5 LLM stage: per-segment model annotation (hard rule)

Every machine-translated segment must carry, **at the model site** (the point where the model produced the
text), an annotation record with these English keys: `segment_id`, `direction`, `model_id`,
`prompt_template_ref`, `timestamp_utc`, `linkages_run`, `annotation_site` (literal `"model"`),
`policy_precheck_ref` (P0 reference), `tenpoint_verdict` (starts `"PENDING"`). The record lives in the
segment ledger (§9); every translated artifact stays traceable to its record.

Zero annotation on a machine-translated segment = pipeline violation, equivalent to undisclosed silent
machine translation. Annotation is not optional metadata: it is the disclosure obligation itself, graded
P0 at the sensitivity level transcribed in §7 (concealed AI generation without disclosure is a
retraction-class offense). Human-translated segments carry `model_id: "human"` and the same ledger row;
the ledger does not distinguish by privilege, only by site.

## §6 Human ten-point single-face

**Why this gate exists** (first-hand card): mechanical comment checks of the gate4 family are blind on
English-face files — `FIELD_SPECS` matches Chinese field labels only, so an English-face file falls outside
the machine word list and its "missing field" reports are not FAIL evidence (card
`D:/ComplexAnalysis/attn/cards/E-STAGING-20261025-GATE4-英形字段盲区二度.md`, first-hand read). The human
ten-point review is the substitute gate on those faces.

**Single-face meaning**: the review inspects the delivered target-face artifact as-is (one side, one pass,
verdict per point with original-line citation). It does not re-translate, does not dual-edit, and does not
modify the source; a FAIL item returns to the dispatcher with the citation (fail-loud).

**Source transcription** (zero-tamper; source:
`D:/ComplexAnalysis/attn/.zcode/agents/free-tenpoint.md`, lines 9-19; carrier: the human ten-point
single-face review agent; standard chain: annotation standard whitepaper v1.8): the verbatim Chinese
transcription of the ten points is preserved byte-exact in the sibling `.zh.md` archive of this SPEC and in
the source original; the casting-session check confirmed all 11 source lines matched byte-exact after
stripping the `> ` quote prefix, missing=0 (§13 check 5).

**The ten points (English rendering of the archived transcription)**: one verdict per file per point with
line citations; (1) five-field English header in order Mission/Dependencies/References/Constructivity/Build; (2) one
business sentence per field; (3) no process narrative, log paths, pitfall-card references, budget notes,
or revision history in headers; (4) `Section n.` English banner form with a math-content topic name;
(5) stepping comments in English on submission/delivery faces; (6) real identifiers only, math reasons in
proof comments; (7) zero process jargon per the whitepaper §4 mapping; (8) zero admission-form English
tokens (context judged, bare-grep false positives expected); (9) statement-level provenance kept external,
References at name level; (10) header line-count 1:1 vs the 30-line cap conflicts resolved only by a
registered REVIEW waiver. Frame verdicts: `ALL-PASS` / `N-FAIL` / `BLOCKED`.

Scope note (honest): the ten points are comment/header-face review points. They gate the translated
artifact's comment surface; they are not a semantic review of mathematical content, which stays with the
content owners.

## §7 AI policy pre-check annotation (P0)

**Rule**: before P2 runs against a target surface, the run records a P0 annotation naming: target surface
(repo face / paper face / review-visible supplementary material), the applicable AI-usage regime for that
surface, the disclosure obligations triggered, and any red line that forbids LLM use on that surface. If
the target regime forbids AI-generated text, the pipeline **refuses** (fail-loud, stage P0 exit) instead of
translating. Refusal is a legal outcome and is ledgered.

**Source transcription** (zero-tamper; source:
`D:/ComplexAnalysis/规范术语/术语表-通用-项目级-20260921.md` §4.6, lines 297-298): the verbatim Chinese
transcription of items D and E is preserved byte-exact in the sibling `.zh.md` archive of this SPEC and in
the source original (casting check: §13 check 5).

**The D/E items (English rendering of the archived transcription)**: D grades review sensitivity (P0 = retraction class:
concealed AI generation, AI ghost-writing, fabricated references, overclaiming, internal-workflow
exposure on review-visible faces). E grades official AI-use regimes across three tracks — education
(Degree Law + ministry guidance + university rules), publication (the AIGC boundary guide, 3rd edition
2025-12-08: allowed / disclose / forbidden; no uploads of unpublished manuscripts under review), and
journal line (disclosure three-piece set: usage statement, in-text marking, prompt comparison record);
the Chinese disclosure skeleton is the three-piece set.
