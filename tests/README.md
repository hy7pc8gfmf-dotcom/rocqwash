# tests/: rocqwash self-test suite

> Purpose.  The repository's self-test suite: 87 statically rostered cases (the
>   `CASES` roster in `tests/run_tests.sh`) covering every tool family with
>   positive and negative judgments; the per-case tables below are the evidence
>   surface for each roster entry, and the live count is always the roster.
>
> Interface.  `bash tests/run_tests.sh` (exit 0 all green / exit 1 any red);
>   `ROCWASH_TESTS_FAIL_PROBE=1` injects one always-red case for the suite's
>   own self-check; `ROCWASH_TESTS_ONLY` / `ROCWASH_TESTS_EXCLUDE` /
>   `ROCWASH_ADVISORY_ROSTER` select or quarantine cases; `ROCWASH_CLEAN=1`
>   skips canonical-environment auto-detection.
>
> Dependencies.  bash 3.2+ and python3; the rostered test faces under tests/;
>   the canonical pointers (`ROCWASH_CANON_*`) and the guarded compile-arc
>   switch (`ROCWASH_ROCQ` / `GATE7_PROBE_SCRIPT` / `GATE6_SCRIPT` /
>   `BORN_WORLD_ROCQ`), probed by `tests/run_tests.sh`.
>
> Evidence.  Every case below cites the tool face it drives and the exact
>   criteria it asserts.  `tools/doc_lint.py` check 2 pins the roster count;
>   its two count-anchor shapes are kept verbatim as data faces (backticked,
>   so the normalization lint's masking applies): `覆盖面（87 例）` and
>   `预期 87 过`: both read 87 and must stay in step with the roster.
>
> Exit-codes.  Suite level: 0 = all green (SKIP not counted red), 1 = any red;
>   a case exits 111 = SKIP when the canonical environment is absent; the
>   per-case contract is [CONTRIBUTING.md §4](../CONTRIBUTING.md).

## Running

```bash
bash tests/run_tests.sh          # all green EXIT 0; any red EXIT 1; idempotent and repeatable
```

Suite self-check (verifies the "any red EXIT 1" contract; injects one always-red case):

```bash
ROCQWASH_TESTS_FAIL_PROBE=1 bash tests/run_tests.sh   # expected: 87 passing / 1 failing / EXIT 1
```

## Format notes

- **Minimal fixtures**: everything under `fixtures/` is made by this suite itself; no large external artifacts.
  One exception, `retrofit_cn_sample.v` (842 lines + trailing newline): the line-shape assertions of
  `retrofit_gate7_irr.py` (843 lines, the L34 separator line, the L36 Require line, the per-line
  `mod.M` anchors) are hardcoded; that fixture is mechanically synthesized from the `mod.M` anchor
  table (`python3 tests/test_retrofit_dryrun.py --regen` rebuilds it); its content has zero external material.
- **How the hardcoded-script cases are driven**: `retrofit_gate7_irr.py` and `_abl1_wash.py` have no CLI;
  their paths are hardcoded (`retrofit_gate7_irr.py:7-11`, `_abl1_wash.py:10`).  The tests drive the real
  `main()` onto fixtures via module import + constant patching; the hardcoded script paths are never touched
  (the adaptation dry run's write requests are all intercepted into memory; the mechanical proof of
  zero writes to disk; wash writes only an mktemp temp directory, deleted when the test ends).
- **Idempotence**: `python3 -B` bans `__pycache__`; the temp log is mktemp + trap cleanup; zero writes into the
  repository.  Repeated runs are byte-identical.
- **Observed behavior (fact, not defect speculation)**: on replay `_abl1_wash.py` APPLYs
  `abl_audit_base_v7.v:require` once more; its `new` has `old` as a prefix, and the tool's SKIP criterion
  requires `c_old==0`, so that tag is never satisfied (the `test_wash_fixture.py` idempotence judgment
  asserts dynamically on the old⊂new set).
- Exit-code contract per [CONTRIBUTING.md §4](../CONTRIBUTING.md): `0` = pass, `2` = assertion failure
  (`--expect` etc.), `9` = missing file; at the suite level `0` = all green (**including SKIP**; SKIP is not
  counted red), `1` = any red; a case exiting `111` = SKIP (canonical environment absent, the case yields;
  the canonical machine always runs the full true sweep).

> **gate4 pre-scan three invariants (side note to the contract paragraph; registered in the v10 round)**; gate4
> (`verify/gate4_comment_guard.py`) must observe three rules when pre-scanning a Set repository tree:
> ① **the pre-scan must run from the Set repository root with absolute paths** (the misplaced-cwd spurious-pass

> (`gate4_comment_guard.py:732`, the `check_file` parameter at `:379`, the over-cap check at `:527-534`);
> ③ **the five dotted field shapes** `Mission.` / `Dependencies.` / `References.` / `Constructivity.` /
> `Build.` (the `FIELD_SPECS` five-field dotted-English regex: `gate4_comment_guard.py:188-194`).
> [Provenance: rule 1 and the "CI whole-tree contract" come from the v10-round task instruction; the cap
> values in ② and the five-field word shapes are on-disk tool-side anchors.  See the v10 section of
> `更新账.md`.]
